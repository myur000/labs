# Задание 2.4. Проверка изменений веб-страниц

[← Задания DevOps](../README.md) · [Все учебные работы](../../README.md)

## Условие

Написать скрипт, который обходит страницы из файла `link.txt`, проверяет, изменились ли они с последнего обхода, и сохраняет результат в `report.txt`.

## Решение

Скрипт **[check_pages.py](check_pages.py)** загружает страницы и вычисляет SHA-256 содержимого каждой из них. Хеши сохраняются в `hashes.json` между запусками. Новый хеш сравнивается с предыдущим, после чего в отчет записывается один из четырех статусов:

| Статус | Значение |
| --- | --- |
| `NEW` | Страница успешно получена впервые; предыдущего хеша нет. |
| `OK` | Содержимое совпало с последней успешно полученной версией. |
| `CHANGED` | Содержимое отличается от последней успешно полученной версии. |
| `ERROR` | Страницу не удалось получить: ошибка сети, HTTP или адреса. |

Сравнение выполняется с **последним успешным обходом**. При ошибке загрузки прежний хеш сохраняется, а HTML страницы с HTTP-ошибкой не становится новым эталоном.

## Окружение и запуск

Нужен Python 3 с поддержкой HTTPS и библиотека `requests`. Для нового окружения рекомендуется Python 3.11 или новее. Скрипту нужны права читать `link.txt`, создавать и обновлять файлы состояния и отчета. Для внешних сайтов требуется доступ к сети.

Из папки `devops/task-2.4` выполнить:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 check_pages.py
```

На Windows можно использовать `python` вместо `python3`, а окружение активировать в PowerShell командой `.venv\Scripts\Activate.ps1`.

**Приложенный `link.txt` содержит адреса локального учебного сервера. Перед проверкой этих адресов нужно запустить `demo_server.py`, как описано ниже.** Для обычного использования заменить адреса в `link.txt` своими полными HTTP/HTTPS-ссылками, например:

```text
https://example.com/
https://www.python.org/
```

Все файлы читаются и сохраняются рядом со скриптом, независимо от текущего каталога терминала. Пустые строки и строки-комментарии с `#` пропускаются. Пробелы по краям удаляются, повторяющийся URL проверяется один раз. При каждом запуске `report.txt` перезаписывается.

В репозитории приложен `hashes.json` после третьего проверочного обхода. Для демонстрации самого первого обхода его нужно удалить, сбросив историю. Если файл отсутствует, скрипт создаст его автоматически. Удаление состояния не требуется при обычных повторных проверках.

## Как работает скрипт

1. Читает адреса из `link.txt`.
2. Загружает прежние хеши из `hashes.json`. Если файла еще нет, использует пустой словарь.
3. Для каждого адреса выполняет GET-запрос с тайм-аутом сетевых операций 10 секунд и заголовком User-Agent.
4. Проверяет HTTP-результат. После обычных перенаправлений конечный ответ должен иметь код 200–299.
5. Вычисляет хеш тела ответа:

   ```python
   current = hashlib.sha256(response.content).hexdigest()
   ```

6. Сравнивает его с сохраненным значением и выбирает `NEW`, `OK` или `CHANGED`. При ошибке выбирает `ERROR` и продолжает проверять остальные адреса.
7. Между запросами делает паузу 1 секунду, затем сохраняет отчет и обновленные хеши.

Хеш вычисляется по байтам тела ответа, без преобразования HTML в текст. Для SHA-256 `hexdigest()` возвращает строку из 64 шестнадцатеричных символов. Это компактный признак содержимого, а не шифрование и не сохраненная копия страницы. Совпадение хешей служит практической проверкой отсутствия изменений; возможность коллизии теоретически существует.

Файл состояния содержит словарь `URL → хеш`. Для его обновления сначала записывается временный файл, а затем готовый файл заменяет старый. Если существующий JSON поврежден или имеет неверную структуру, программа сообщает об ошибке и не сбрасывает историю молча. Запускать несколько копий скрипта одновременно не предполагается.

## Практическая проверка

Проверка выполнена **19.10.2026**, Python **3.12.14**, `requests` **2.34.2**. Выполнены пять отдельных запусков основного скрипта с настоящими HTTP-запросами к локальному серверу. Между запусками сохранялся `hashes.json`.

Во входном файле три адреса: изменяемая страница, постоянная страница и заведомо отсутствующая страница для проверки HTTP 404.

| Обход | Действие перед запуском | page.html | stable.html | missing.html |
| --- | --- | --- | --- | --- |
| [Первый](examples/report-first.txt) | Истории нет, страница версии 1. | `NEW` | `NEW` | `ERROR` |
| [Второй](examples/report-second.txt) | Ничего не менялось. | `OK` | `OK` | `ERROR` |
| [Третий](examples/report-third.txt) | Содержимое page.html заменено версией 2. | `CHANGED` | `OK` | `ERROR` |
| [Ошибка](examples/report-error.txt) | page.html временно удалена, сервер отвечает 404. | `ERROR` | `OK` | `ERROR` |
| [Восстановление](examples/report-recovery.txt) | Возвращено то же содержимое версии 2. | `OK` | `OK` | `ERROR` |

Отдельно подтверждено, что ошибка загрузки не изменила сохраненный хеш. После восстановления сравнение выполнилось с версией 2, полученной при третьем обходе.

### Полученный report.txt после изменения страницы

```text
[CHANGED] http://127.0.0.1:8000/page.html — контент изменился
[OK] http://127.0.0.1:8000/stable.html — без изменений
[ERROR] http://127.0.0.1:8000/missing.html — 404 Client Error: File not found for url: http://127.0.0.1:8000/missing.html
```

Наличие `ERROR` здесь ожидается: адрес `missing.html` специально включен в пример и не существует. Из-за него код завершения равен `1`, хотя остальные страницы проверены и отчет сохранен. Когда все адреса успешно обработаны, программа возвращает `0`; обнаруженное изменение `CHANGED` само по себе ошибкой не считается.

### Как повторить демонстрацию на защите

1. Из папки задания в первом терминале запустить учебный сервер:

   ```bash
   python3 demo_server.py
   ```

2. Для первого обхода удалить учебный `hashes.json`. Во втором терминале запустить `python3 check_pages.py` и открыть `report.txt`: две существующие страницы получат `NEW`.
3. Повторить запуск без редактирования файлов: эти страницы получат `OK`.
4. Изменить текст заголовка в `site/page.html`, сохранить файл и снова запустить скрипт: эта страница получит `CHANGED`.
5. Запустить еще раз без изменений: для нее снова будет `OK`, поскольку эталон уже обновлен.

Учебный сервер работает на `127.0.0.1:8000`; этот порт должен быть свободен. Он останавливается через Ctrl+C. Если сервер не запущен, локальные адреса получат `ERROR`, а прежние хеши сохранятся. Для демонстрации без специально добавленной ошибки можно убрать строку `missing.html` из `link.txt`.

## Ограничения

Сравнивается полученное содержимое целиком. Динамические даты, реклама или случайные идентификаторы тоже могут вызвать `CHANGED`, даже если основной текст не изменился. Скрипт не выполняет JavaScript и не загружает отдельно картинки, CSS или другие ресурсы: проверяется только тело ответа по URL. Он обнаруживает факт изменения, но не показывает конкретные отличия.

История содержит только последний успешный хеш каждого адреса, а не все версии страницы. Хеши адресов, удаленных из списка, сохраняются: если адрес вернуть, сравнение продолжится с его последней известной версией. Проверка выполняется один раз при запуске; последующие обходы нужно запускать отдельно.

## Подготовка к защите

| Вопрос | Ответ |
| --- | --- |
| Зачем нужен hashes.json? | Он сохраняет состояние между процессами. Без него каждый запуск считался бы первым. |
| Что такое хеш? | Значение фиксированной длины, вычисленное из содержимого. По нему удобно сравнивать версии. |
| Почему SHA-256, а не hash()? | Встроенный `hash()` не предназначен для постоянного хранения такого состояния и для строк/байтов обычно меняется между процессами. SHA-256 воспроизводим для одинаковых байтов. |
| Почему используется response.content? | Это байты тела ответа; они не зависят от выбранного при преобразовании в строку способа декодирования. |
| Что происходит при первом запуске? | Для успешно полученного нового URL ставится `NEW` и сохраняется его хеш. |
| Почему после CHANGED следующий обход дает OK? | При успешном обходе новый хеш становится эталоном. |
| Что происходит при HTTP 404 или тайм-ауте? | Ставится `ERROR`, прежний хеш сохраняется, остальные адреса продолжают проверяться. |
| Зачем нужны задержка и тайм-аут? | Задержка уменьшает частоту запросов; тайм-аут ограничивает ожидание сетевых операций. |
| Как сбросить историю? | Удалить `hashes.json`; следующий успешный обход каждого URL даст `NEW`. |
| Почему страница может считаться измененной без видимых отличий? | Мог измениться невидимый участок HTML, дата, реклама или иной динамический фрагмент. |
| Как показать, что задача работает? | Выполнить обход, повторить его, изменить учебный HTML и выполнить обход еще раз, сравнив статусы. |
