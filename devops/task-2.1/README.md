# Отчет по заданию 2.1

## Цель работы

Изучить скрипт для анализа лога Nginx, определить необходимые библиотеки и окружение, затем выполнить часть его функций.

Скрипт должен находить IP-адреса, с которых получено больше 50 ошибок HTTP 404. Код 404 означает, что запрошенная страница или файл не найдены. Много таких ответов может указывать на перебор адресов, но само по себе не доказывает атаку.

## 1. Какие библиотеки используются

В исходном скрипте используются:

| Библиотека | Для чего нужна |
| --- | --- |
| `re` | Ищет в тексте фрагменты по шаблону. В исходнике `re.findall()` извлекает IP из записей с ошибкой 404. |
| `collections.Counter` | Считает повторы: сколько ошибок пришлось на каждый IP. Например, результат может быть `{"192.0.2.10": 51}`. |
| `requests` | Выполняет HTTP-запросы. `requests.post()` отправляет сообщение в Telegram через API бота. |

`re` и `collections` входят в Python. `requests` устанавливается отдельно.

В приведенной ниже версии добавлены два стандартных модуля: `os` читает настройки Telegram из переменных окружения, а `ipaddress` проверяет, что найденная строка является настоящим IP-адресом.

## 2. Какое окружение требуется

- Python 3 и установленная библиотека `requests`.
- Текстовый файл лога и право его читать.
- Формат строки лога, соответствующий используемому шаблону.
- Для отправки в Telegram — интернет, токен бота и ID чата. Для личного чата пользователь должен предварительно начать диалог с ботом.

Установка библиотеки:

```bash
python3 -m pip install requests
```

Для анализа готового файла работающий Nginx не нужен. Можно использовать скачанный лог или учебный пример.

## 3. Измененный скрипт

Для этого отчета подготовлен упрощенный вариант `analyze_simple.py`. Он анализирует `sample_access.log`, выводит число ошибок по каждому IP и предупреждает о превышении порога. Отправка в Telegram включается отдельной настройкой.

В исходном задании адрес Telegram указан неверно. Исправленный адрес: `https://api.telegram.org/bot<TOKEN>/sendMessage`.

### Полный код analyze_simple.py

```python
import os
import re
from collections import Counter
from ipaddress import ip_address

import requests

# 1. Настройки: файл лога, порог и включение Telegram.
LOG_FILE = "sample_access.log"
THRESHOLD = 50
SEND_TELEGRAM = False
TOKEN = os.getenv("TELEGRAM_TOKEN", "")
CHAT_ID = os.getenv("CHAT_ID", "")

if SEND_TELEGRAM and (not TOKEN or not CHAT_ID):
    raise SystemExit("Задайте TELEGRAM_TOKEN и CHAT_ID.")

# 2. Шаблон: IP в начале строки и статус 404 после запроса.
pattern = re.compile(
    r'^(\S+)\s+\S+\s+\S+\s+\[[^\]]+\]\s+"[^"]*"\s+404\s'
)
counts = Counter()

# 3. Читаем лог и считаем ошибки 404 для каждого IP.
try:
    with open(LOG_FILE, "r", encoding="utf-8", errors="replace") as log:
        for line in log:
            match = pattern.search(line)
            if not match:
                continue
            try:
                ip = str(ip_address(match.group(1)))
            except ValueError:
                continue
            counts[ip] += 1
except OSError as error:
    raise SystemExit(f"Не удалось прочитать лог: {error}")

# 4. Показываем результат подсчета.
print("Количество ошибок 404 по IP:")
for ip, count in counts.items():
    print(f"{ip}: {count}")

# 5. Выявляем превышение порога и формируем предупреждение.
for ip, count in counts.items():
    if count > THRESHOLD:
        message = f"Подозрительная активность: IP {ip}, ошибок 404 — {count}."
        print(message)

        # 6. При включенной настройке отправляем сообщение в Telegram.
        if SEND_TELEGRAM:
            try:
                response = requests.post(
                    f"https://api.telegram.org/bot{TOKEN}/sendMessage",
                    json={"chat_id": CHAT_ID, "text": message},
                    timeout=10,
                )
                response.raise_for_status()
                if response.json().get("ok") is not True:
                    raise ValueError("Telegram не подтвердил отправку.")
                print("Сообщение отправлено в Telegram.")
            except (requests.RequestException, ValueError):
                print("Не удалось отправить сообщение в Telegram.")
```

## 4. Как работает код

### Шаг 1. Задаются настройки

`LOG_FILE` — имя файла, который нужно прочитать. `THRESHOLD = 50` — порог количества ошибок. `SEND_TELEGRAM = False` означает, что предупреждения пока выводятся только в терминал.

`os.getenv()` получает токен и ID чата из переменных окружения. Это позволяет не записывать реальные данные бота в исходный код на GitHub.

### Шаг 2. Подготавливается шаблон поиска

`re.compile()` создает регулярное выражение — шаблон для распознавания нужных строк.

В строке вида:

```text
192.0.2.10 - - [19/Oct/2026:00:00:00 +0700] "GET /missing HTTP/1.1" 404 123 "-" "StudyClient/1.0"
```

скрипт извлекает `192.0.2.10`, потому что после запроса в кавычках указан статус 404.

Основные части шаблона:

| Часть | Значение |
| --- | --- |
| `^` | Начало строки. |
| `(\S+)` | Первое поле без пробелов. Скобки сохраняют его для извлечения IP. |
| `\s+` | Один или несколько пробельных символов между полями. |
| `\[[^\]]+\]` | Поле времени в квадратных скобках. |
| `"[^"]*"` | Запрос в двойных кавычках. |
| `404\s` | Код ответа 404 с пробельным разделителем после него. |

За счет положения кода после запроса число `404` внутри самого URL не считается ошибкой.

### Шаг 3. Файл читается построчно

`with open(...)` открывает файл, а `for line in log` перебирает его строки. После выхода из блока `with` файл закрывается автоматически.

`pattern.search(line)` проверяет очередную строку. Если совпадения нет, `continue` пропускает ее и переходит к следующей.

### Шаг 4. Извлекается IP и увеличивается счетчик

`match.group(1)` возвращает первое сохраненное поле — адрес клиента. `ip_address()` проверяет его. Например, некорректный адрес `999.1.1.1` будет пропущен.

`counts[ip] += 1` прибавляет одну ошибку к счетчику этого адреса. Для нового IP счетчик начинается с нуля.

### Шаг 5. Результат сравнивается с порогом

`counts.items()` позволяет перебрать пары «IP — количество ошибок».

Условие `count > THRESHOLD` проверяет, превышен ли порог. При 50 ошибках предупреждения нет. При 51 ошибке оно появляется.

### Шаг 6. При необходимости отправляется сообщение

Если `SEND_TELEGRAM = True`, `requests.post()` отправляет запрос к API Telegram. В `json` передаются `chat_id` — получатель и `text` — текст сообщения.

`timeout=10` ограничивает ожидание сетевых операций. `raise_for_status()` обнаруживает HTTP-ошибки, а поле `ok` в ответе Telegram подтверждает успешную отправку.

`try/except` обрабатывает ожидаемые ошибки: например, недоступный файл, некорректный IP или сбой отправки сообщения.

## 5. Запуск и результат

Скрипт и учебный `sample_access.log` должны находиться в одной папке. В репозитории файл лога уже находится в папке задания 2.1.

Из этой папки выполнить:

```bash
python3 analyze_simple.py
```

При проверке 22.10.2026 использован учебный лог: у `192.0.2.10` — 51 ошибка 404, у `198.51.100.20` — 50. Другие статусы и некорректные строки не учитываются.

Фактический результат:

```text
Количество ошибок 404 по IP:
192.0.2.10: 51
198.51.100.20: 50
Подозрительная активность: IP 192.0.2.10, ошибок 404 — 51.
```

Для работы с настоящим логом нужно изменить `LOG_FILE`, например на `/var/log/nginx/access.log`.

Для Telegram нужно установить `SEND_TELEGRAM = True` и перед запуском задать реальные значения:

```bash
export TELEGRAM_TOKEN='токен_бота'
export CHAT_ID='id_чата'
python3 analyze_simple.py
```

Реальная отправка в Telegram в рамках работы не проверялась: токен и ID чата не предоставлялись. Выполнена часть задания с анализом лога и выявлением превышения порога.

## Вывод

Скрипт читает лог, находит записи с кодом 404, считает их для каждого IP и выводит предупреждение при количестве больше 50. Практическая проверка подтвердила: 51 ошибка вызывает предупреждение, ровно 50 — не вызывает.

Подсчет ведется по всему файлу, без ограничения по времени. Это нужно учитывать при объяснении результата.
