# Задание 2.2. Проверка доступности сайтов

[← Задания DevOps](../README.md) · [Все учебные работы](../../README.md)

## Условие

Написать на Python скрипт, который читает адреса сайтов из файла `link.txt`, проверяет их доступность и записывает результат в файл `report.txt` в формате:

```text
адрес -> Ok
адрес -> Error
```

## Решение

Скрипт **[check_links.py](check_links.py)** читает адреса по одному на строку, отправляет HTTP GET-запрос и сохраняет результат проверки. Он работает с HTTP и HTTPS, автоматически следует обычным HTTP-перенаправлениям и проверяет конечный ответ:

- `Ok` — получен конечный HTTP-ответ с кодом 200–299.
- `Error` — код ответа вне диапазона 200–299, ошибка подключения, DNS, TLS, тайм-аут либо некорректный адрес.

Если один сайт недоступен, программа продолжает проверять остальные. Пустые строки пропускаются, пробелы по краям удаляются, порядок адресов и повторяющиеся записи сохраняются. При каждом запуске `report.txt` перезаписывается. В отчет попадают только строки требуемого формата.

Условие не определяет, какие HTTP-коды считать успешными, поэтому в этой работе доступность определена через конечный ответ 2xx. Например, сервер, ответивший 403, доступен по сети, но указанный ресурс для скрипта недоступен и получает `Error`.

## Окружение и используемые модули

Нужен Python 3, права на чтение `link.txt` и запись `report.txt`. Для настоящих сайтов нужен доступ к сети, а для HTTPS — рабочее окружение проверки сертификатов. Сторонние библиотеки не используются, установка через pip не требуется. Проверено на Python **3.9.6**.

| Модуль | Назначение |
| --- | --- |
| `urllib.request` | `Request` формирует GET-запрос, `urlopen` открывает адрес с тайм-аутом. |
| `urllib.error` | Обработка ошибок HTTP и URL. |
| `urllib.parse` | Проверка схемы, имени узла и порта URL. |
| `http.client` | Обработка ошибок HTTP-протокола. |
| `pathlib` | Пути к входному файлу и отчету. |
| `argparse` | Необязательные параметры командной строки. |
| `math` | Проверка корректности значения тайм-аута. |
| `sys` | Вывод сообщений об ошибках и код завершения программы. |

## Запуск с собственными адресами

Скачать папку задания и заменить содержимое `link.txt` своими адресами. Указывать полные URL с `http://` или `https://`, по одному на строку, например:

```text
https://example.com/
https://www.python.org/
```

Выполнить:

```bash
python3 check_links.py
```

Файл `report.txt` появится рядом со скриптом. По умолчанию входной и выходной файлы ищутся в папке скрипта, поэтому команда работает и при запуске из другого каталога. На Windows вместо `python3` можно использовать `python`.

Дополнительно можно указать другие файлы и тайм-аут:

```bash
python3 check_links.py --input link.txt --output report.txt --timeout 5
```

Тайм-аут ограничивает ожидание сетевых операций, а не общее время всей проверки. По умолчанию он равен 10 секундам. Некорректное значение тайм-аута отклоняется. Если входной файл отсутствует или отчет невозможно записать, программа сообщает об ошибке и завершается с ненулевым кодом.

## Практическая проверка

Для воспроизводимости в приложенном **[link.txt](link.txt)** используются адреса локального учебного сервера **[demo_server.py](demo_server.py)**. Внешние сайты при этой проверке не использовались. Основной скрипт может проверять любые доступные HTTP/HTTPS-адреса из файла.

В первом терминале из папки задания запустить:

```bash
python3 demo_server.py
```

Во втором терминале выполнить:

```bash
python3 check_links.py
```

Учебный сервер открывается на `127.0.0.1:8000`. Если порт занят, можно запустить сервер с `--port 8001` и заменить порт в `link.txt`. После проверки сервер останавливается через Ctrl+C. Без запуска учебного сервера его адреса получат `Error`.

### Входной файл link.txt

```text
http://127.0.0.1:8000/ok
http://127.0.0.1:8000/redirect
http://127.0.0.1:8000/missing
http://127.0.0.1:8000/server-error
неверный-адрес
ftp://example.com/
```

### Полученный файл report.txt

Фактически созданный файл: **[report.txt](report.txt)**.

```text
http://127.0.0.1:8000/ok -> Ok
http://127.0.0.1:8000/redirect -> Ok
http://127.0.0.1:8000/missing -> Error
http://127.0.0.1:8000/server-error -> Error
неверный-адрес -> Error
ftp://example.com/ -> Error
```

Первый адрес возвращает HTTP 200. Второй перенаправляет на первый и тоже получает `Ok`. Третий возвращает 404, четвертый — 500. Последние два адреса некорректны для проверки HTTP/HTTPS. Программа обработала все 6 строк и завершилась с кодом `0`.

Фактический вывод сохранен в **[verification.txt](verification.txt)**.

### Автоматические проверки

```bash
python3 -m unittest -v
```

В **[test_check_links.py](test_check_links.py)** пройдены **12 тестов**: HTTP 200, 404 и 500; перенаправление; некорректные адреса; тайм-аут; ошибка DNS; формат отчета, порядок, дубликаты и пустые строки; отсутствие входного файла; защита от перезаписи входного файла; пустой файл; некорректный тайм-аут.

HTTP-ответы и перенаправление проверены настоящими запросами к локальному серверу. Тайм-аут и ошибка DNS проверены с подменой сетевого вызова. Тесты не зависят от доступности внешних сайтов.

```text
Ran 12 tests
OK
```

Реализован Python-скрипт, который читает адреса из `link.txt`, проверяет их доступность и записывает `report.txt` в требуемом формате `адрес -> Ok/Error`. Работа подтверждена запуском на учебном сервере и автоматическими проверками.
